{# The tool tree. One collapsible group per registered child, one visibility control per level, one server row per child. Every control posts to its own route and swaps this whole partial back in, so the three levels never render a stale mark. Constraints that shape the markup: - A tool name comes from the child, so it travels in the form body, never in the URL path. A child that names a tool `../../servers/x/delete` would otherwise produce a link the browser normalises into a different authenticated route. - Every visibility control syncs on `#tools-tree` with `replace`, not `queue`. The response swaps this whole partial, so a queued request would be owned by a form the swap already detached, and htmx would drop it silently. `replace` cancels the in-flight request instead. Note this is cancellation, not ordering: the server may already have accepted the cancelled request, so two clicks inside one request window can still commit out of order. The next render corrects the page. - The root carries `hx-disinherit="*"` at all times, so no control inside inherits the poll's swap, sync, or trigger. Every control declares its own `hx-target` and `hx-swap`; the `Details` control targets the dialog and inherits no sync, so a poll never drops it. - The root carries the poll only while a child is `starting`. The poll sends no parameters and this partial renders every group collapsed. The browser owns the open state: `dashboard.html` records it on `htmx:beforeSwap` and restores it on `htmx:afterSwap`. - The namespace control sits below the server row, not inside the ``. Clicking any child of a `` toggles the group, so a control placed there could not be operated without JavaScript. - The `mcpflow` group is the built-in admin server. It has no child record, so its header shows `built-in` in place of a status, it holds no server row, and its namespace control reads `mcpflow_muted`, not `c.spec.muted`. The root does not cover it, so the root state never disables one of its controls. A pinned row carries a checked, disabled control: visibility never hides that tool, so the admin cannot lock themselves out of the MCP admin surface. #} {% set polling = children | selectattr('status', 'equalto', 'starting') | list | length > 0 %}
